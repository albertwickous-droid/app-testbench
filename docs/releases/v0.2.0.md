# App TestBench v0.2.0

**本地优先的 Android 快速验证工作台，为个人开发者和小微团队补齐“最后一公里”。**
**A local-first Android quick-validation workbench for individuals and small teams.**

云真机平台擅长设备覆盖和并发规模；App TestBench 不正面竞争这两项。它解决的是另一类高频问题：手上已经有一台 Windows 机器和 MuMu，如何在不注册平台、不上传 APK、不排队等待的情况下，把一条 App 验证链路快速跑完，并把失败现场留在本机。

Cloud device farms optimize device coverage and concurrency. App TestBench does not compete on those dimensions. It optimizes the last mile: when you already have a Windows machine and MuMu, how do you run a repeatable app check without uploading an APK, waiting in a queue, or losing the failure evidence?

## 新增能力 / What is new

### 可复现输入与执行前检查

- `--vars-file` / `--var`：扁平变量、类型保留、严格校验，优先级为 CLI > 变量文件 > 环境变量。
- `run --dry-run`：解析最终 flow、设备、变量和预期命令；不连接 MuMu/ADB，不创建运行目录。
- Flow 级 `timeout_seconds` / `--flow-timeout`：在步骤边界收口，后续步骤标记 skipped，teardown 仍会执行。

### 更适合快速验证的编排

- `wait_for_text_gone`：等待 Loading、错误提示或临时遮罩消失。
- Flow `include` / `template`：复用登录、准备数据、清理等片段；检测循环依赖和重复 step id。
- Flow `tags` 与 `suite --tag smoke`：按标签选择 flow，顺序执行，每个 flow 独立运行目录。
- `run --data`：CSV/JSON/YAML 每行生成独立 case，复用同一 flow；聚合 `data-result.json`、HTML 和 JUnit。

### 证据与机器可读契约

- 每次运行生成 `manifest.json`，记录证据路径、大小、媒体类型和 SHA-256；`--keep-runs` 只清理带 manifest 的旧直接子目录。
- APK `sha256` 预检：不匹配时绝不调用 `adb install`。
- 步骤级 logcat 时间窗：默认保留失败步骤窗口，`report.capture_step_logcat` 可设为 `all`。
- `report.redact`：覆盖 JSON、HTML、JUnit、Manifest 和文本证据；截图不做像素级脱敏，分享前仍需人工检查。
- `run --events-jsonl`：实时输出 `flow_start`、`step_start`、`step_end`、`flow_end`，每行立即 flush。
- 新增 `events-v1.schema.json` 和 `collection-result-v1.schema.json`，与原有 `cli-v1`、`result-v1` 一起构成 Draft 2020-12 契约。

## 最短示例 / Quick start

单条 flow：

```powershell
app-testbench validate .\flow.yaml --var APP_PACKAGE=com.example.debug
app-testbench run .\flow.yaml --output .\runs --junit-xml .\runs\junit.xml
```

数据驱动：

```powershell
app-testbench run .\checkout.yaml --data .\checkout-cases.csv --output .\runs
```

Suite + 标签：

```powershell
app-testbench suite .\suite.yaml --tag smoke --output .\runs
```

实时事件：

```powershell
app-testbench run .\flow.yaml --events-jsonl .\runs\events.ndjson
```

## 产物 / Artifacts

单个 flow：

```text
runs/<timestamp>-<flow>/
├── report.html
├── result.json
├── junit.xml          # optional
├── manifest.json
├── screenshots/
├── ui/
└── logs/
```

Suite 或 data-driven：

```text
runs/<timestamp>-<name>/
├── suite-result.json  # or data-result.json
├── suite-report.html  # or data-report.html
├── junit.xml
├── manifest.json
└── cases/
    └── <timestamp>-<flow>/
        ├── report.html
        ├── result.json
        └── manifest.json
```

## 兼容性与边界 / Compatibility and boundaries

- 当前运行时以 Windows + MuMu Player 为主；不是跨品牌设备云，也不提供高并发设备池。
- 本地运行降低上传和平台配置成本，但 MuMu、Windows、Python、ADB 仍是前置条件。
- 截图和 UI 树可能包含敏感信息；`report.redact` 只处理文本证据，不处理像素。
- 真实设备兼容性仍需要在目标 MuMu/Android 版本上抽样验证。
- 本版本的自动验证使用 fake ADB/MuMuManager 后端和仓库测试；没有在本次维护中启动真实 MuMu 或操作 Android 设备。

## 升级 / Upgrade

从 `0.1.1` 升级：

```powershell
python -m pip install --upgrade .
app-testbench --version
app-testbench doctor --json
```

PyPI 发布与 GitHub Release 是两个独立渠道；本文件不表示已经发布到 PyPI，也不表示已经创建远端 tag。
